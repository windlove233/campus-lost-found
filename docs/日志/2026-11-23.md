# 2026 年 11 月 23 日 开工记录

- **当天目标** 明确照片优先发布、寻物提醒和轻量排序的范围，验证现有照片能提供哪些时空信息。
- **讨论结果** 使用 MySQL 与手机网页。发布招领只必填照片，系统尽量提取线索。为失主提供更优候选提醒。排序使用图文、时间和地点特征。
- **实际验证** 用 Pillow 检查三张网图，均缺少 EXIF 原始拍摄时间和 GPS。另生成一张带已知时间与坐标的内存 JPEG，验证两项数据可成功读取。
- **得到的结论** 同一个上传流程要能处理有元数据和缺元数据的照片。网图保留为图文功能样例，时空评测另用有真实场景记录的校园照片。
- **已实现** `photo_metadata.py` 读取原始拍摄时间和 GPS，保留照片提供的时区偏移。缺少字段时输出 `null`，上传时间由后续的发布流程单独记录。
- **复测结果** 四项自动测试通过，覆盖带时区的拍摄时间、西经南纬、缺失字段和不完整 GPS。用命令行逐张读取三张网图，均输出三个 `null`。
- **动手练习** 在项目目录运行 `.\.venv\Scripts\python.exe .\photo_metadata.py .\测试图片1.png`。再换成一张手机拍摄的原图，比较原图和转发后版本的 `captured_at`、`latitude`、`longitude`。把保留和丢失的字段记入日志。
- **数据库环境** 已确认本机安装 MySQL Server 8.0，且本地 `3306` 端口可连通。项目数据库和应用账号的连接验证待数据库练习完成。
- **表结构测试** 用独立的 MySQL 8.0.46 临时实例连续导入两次 `schema.sql`，验证了仅凭照片就能插入招领记录、中文寻物描述能够保存、更新最佳候选可与写入未读提醒放在同一事务中。重复的寻物帖与招领物品配对、长度不符的图片向量均被数据库拒绝。测试结束后已关闭临时实例。
- **正式环境练习** 正式建库、创建项目账号和导入表结构留给学习者亲手操作。练习从辨认三张表的主键、外键和唯一索引开始。
