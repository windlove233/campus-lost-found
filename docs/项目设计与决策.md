# 校园失物招领设计与决策

三周内做出能在 Python 课上离线演示、可供同学在局域网试用的校园失物招领项目。每天安排 30–45 分钟，先讨论实现，再动手验证，最后补齐当天日志。

## 已确认的需求

- 使用 MySQL。首版使用手机可打开的网页，本机用于课堂演示，同学通过局域网试用。
- 发布招领时只必填照片。系统尽量提取时空线索，拾取时间、地点和补充描述均可选。
- 系统发现比之前更匹配的招领物品时提醒失主。设计暂按失主发布寻物帖来保存持续匹配的条件。
- 训练轻量逻辑回归模型，用图文相似度、时间和地点共同给候选物品打分。搜索排序和更优候选提醒复用这个分数。原计划的三种排序对照作为可选实验。

## 已验证的图片线索

三张现有 PNG 为网图，均没有 EXIF 原始拍摄时间与 GPS，可继续用于图文检索演示。另用 Pillow 在内存中生成 JPEG，写入模拟拍摄时间 `2026-11-23 14:30:00` 和示例坐标 `(30.3, 120.15)`，重新打开后成功读回。照片拍摄时间与地点是线索，拾取时间与地点由发布者选填或确认。上传时间单独记录。

## 待讨论的实现方案

### 照片发布与时空线索

读取原始上传照片中的 EXIF 拍摄时间和 GPS。匹配校园地点时，把 GPS 映射到配置好的校园区域。图片包含楼名、门牌或日期文字时，尝试在本机做 OCR，再用校园地点词表识别候选地点。画面中可辨认的场景可以作为额外提示，具体建筑名要有可辨认的文字、GPS 或已验证的地标支持。

每条线索保留来源和确认状态。发布者可以改正自动识别的候选，缺失字段留空也能发布。结果页展示确认过的地点或大致校园区域。MySQL 保存来源、候选值、确认值和图片向量，公开缩略图移除原始 GPS 元数据。

### 寻物帖与提醒

寻物帖必填中文物品描述，可补充大致丢失时间和地点。创建时先在已有招领帖中搜索并记下初始最佳候选。新招领帖入库后，用同一套模型给活跃寻物帖评分。新候选达到验证集定出的提醒分数，并超过先前最佳时，再记录一条提醒。同一个寻物帖和候选物品最多提醒一次，模型更换时先用新版重算比较基准。

建议首版保存站内通知，页面打开时自动刷新未读提醒，关闭网页期间的通知可以重新打开查看。离开网页也能收到的提醒需另定渠道。目前还需确认课堂验收采用哪种方式。

### 轻量排序模型与评测

每条训练记录是一个寻物描述与一条候选招领记录组成的配对。以是否为同一件实物作为标签。正例取真实匹配，负例优先取外观类似但属于其他实物的候选。输入特征用 Chinese-CLIP 余弦相似度、日期距离、校园区域匹配及时间地点缺失标记。先训练带正则化的逻辑回归，观察系数方向以及时空信息缺失时的表现。

先按实物编号分组划分，再生成配对。同一实物的照片和描述不跨训练与评测，评测使用的描述和答案留到最后。用留出的样本检查正确物品能否进入前三、时间地点缺失时排名是否合理。提醒另外检查更优候选、较差候选、重复事件和时空线索缺失的情况。三张网图只用于功能验证。训练和评测使用带实物编号、拍摄或拾取背景以及人工编写描述的校园样本。

#### 逻辑回归样本导出

`ranking_features.py` 提取七个特征。图文相似度是描述与照片的余弦相似度。日期用丢失和拾取的绝对天数差，并附日期缺失标记。地点保留填写的原文，计算楼栋是否相同、楼栋信息是否缺失、房间是否相同、房间信息是否缺失。比如「主教 214 讲台」和「主教学楼 214」的楼栋与房间都匹配，只有「214」时楼栋缺失。缺失标记为 1 时，对应数值的 0 是占位值。首批楼栋别名维护在 `BUILDING_ALIASES`。

1. 在发布页上传校园样本，记下页面返回的招领编号。照片属于同一件实物时，将编号都放在同一个 `object_id` 的 `found_item_ids` 里。
2. 把 `data/training.example.json` 复制为 `data/training.local.json`。替换示例编号，给每件实物标注 `train` 或 `test`，再在 `queries` 为对应的 `object_id` 写寻物描述和可选的日期地点。丢失日期用 `YYYY-MM-DD`，日期地点缺失时填 `null`。每组至少两件不同实物和一条描述才能导出正负样本。这个数量仅够验证流程。
3. 在能启动 Flask 并访问 MySQL 的 VS Code 终端里，从项目根目录运行命令。

```powershell
.\.venv\Scripts\python.exe .\build_ranking_dataset.py .\data\training.local.json .\data\ranking-dataset.local.json
```

导出脚本读取 MySQL 中已保存的图片向量。每条寻物描述和同组的候选照片生成一条配对。若二者的实物编号相同，`label` 为 1，否则为 0。导出的 JSON 含 `feature_names` 和 `rows`，脚本会在终端打印每组正负样本数。训练时用 `features` 预测 `label`，并使用 `split` 划分数据。网页已调用同一个特征函数，目前展示按余弦相似度排序的前三条结果。

## 首版模块输入输出草案

| 模块 | 输入 | 输出 |
|---|---|---|
| 招领发布 | 照片必填，拾取日期、校园区域和说明选填 | 保存成功返回物品编号。保存照片、已确认的位置与日期、照片线索以及图片向量 |
| 照片线索 | 原始图片 | 拍摄时间、GPS 和可用的候选区域，附带各自的来源。无信息时相应字段留空 |
| 图文检索 | 中文描述、招领图片向量，可选丢失日期和校园区域 | 每件候选的物品编号、图文相似度与可用时空特征 |
| 逻辑回归 | 一组查询与候选之间的图文相似度、日期差、校园区域匹配及缺失标记 | 一个匹配分数和排序模型版本，供搜索与提醒复用 |
| 搜索结果 | 候选分数和物品信息 | 按分数降序显示最多三条。每条附照片、确认过的拾取信息和物品编号 |
| 寻物提醒 | 已保存的寻物帖、新发布的招领物品、同版本基准分 | 当候选超过之前的最佳结果并达到提醒门槛时，生成一条未读提醒 |

图片和文字向量由同一版 Chinese-CLIP 产生。建议统一保存为 512 维、每维 4 字节的小端 `float32`，与 MySQL 的 `VARBINARY(2048)` 对应。搜索和提醒使用相同的特征计算方式。日期或地点缺失时，向模型提供缺失标记。拍摄地点与拍摄时间仍单独存为照片线索，由发布者确认后才写入拾取字段。

联调的第一个样例是只上传一张照片，得到一个招领编号，然后输入中文描述，在结果里看到同一编号。发布时如何展示或确认自动识别结果、提醒页面如何呈现，留到对应页面设计讨论。

## 三周里程碑

| 周次 | 动手任务 | 验收 |
|---|---|---|
| 第一周 | 接好 MySQL、发布与查询网页，提取 EXIF 并缓存图片向量 | 只上传照片即可发布，重启后能搜到，缺失线索仍可正常检索 |
| 第二周 | 抽取画面文字线索，接通寻物帖和更优候选提醒，采集与标注数据 | 准备至少一组更优、较差和重复候选，演示提醒只在合适时触发 |
| 第三周 | 训练并接入轻量排序模型，完成手机试用和断网彩排 | 展示模型怎样使用时空线索，在三分钟内走通照片发布、寻物检索和提醒 |
