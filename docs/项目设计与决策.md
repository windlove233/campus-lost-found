# 校园失物招领设计与决策

三周内做出能在 Python 课上离线演示、可供同学在局域网试用的校园失物招领项目。每天安排 30–45 分钟，先讨论实现，再动手验证，最后补齐当天日志。

## 已确认的需求

- 使用 MySQL。首版使用手机可打开的网页，本机用于课堂演示，同学通过局域网试用。
- 发布招领时只必填照片。系统尽量提取时空线索，拾取时间、地点和补充描述均可选。
- 系统发现比之前更匹配的招领物品时提醒失主。设计暂按失主发布寻物帖来保存持续匹配的条件。
- 训练轻量逻辑回归模型，用图文相似度、时间和地点共同给候选物品打分。搜索排序和更优候选提醒复用这个分数。原计划的三种排序对照作为可选实验。

## 已验证的图片线索

三张现有 PNG 为网图，均没有 EXIF 原始拍摄时间与 GPS，可继续用于图文检索演示。另用 Pillow 在内存中生成 JPEG，写入模拟拍摄时间 `2026-11-23 14:30:00` 和示例坐标 `(30.3, 120.15)`，重新打开后成功读回。照片拍摄时间与地点是线索，拾取时间与地点由发布者选填或确认。上传时间单独记录。

## 待讨论的实现方案

### 照片发布与时空线索

读取原始上传照片中的 EXIF 拍摄时间和 GPS。匹配校园地点时，把 GPS 映射到配置好的校园区域。图片包含楼名、门牌或日期文字时，尝试在本机做 OCR，再用校园地点词表识别候选地点。画面中可辨认的场景可以作为额外提示，具体建筑名要有可辨认的文字、GPS 或已验证的地标支持。

每条线索保留来源和确认状态。发布者可以改正自动识别的候选，缺失字段留空也能发布。结果页展示确认过的地点或大致校园区域。MySQL 保存来源、候选值、确认值和图片向量，公开缩略图移除原始 GPS 元数据。

### 寻物帖与提醒

寻物帖必填中文物品描述，可补充大致丢失时间和地点。创建时先在已有招领帖中搜索并记下初始最佳候选。新招领帖入库后，用同一套模型给活跃寻物帖评分。新候选达到验证集定出的提醒分数，并超过先前最佳时，再记录一条提醒。同一个寻物帖和候选物品最多提醒一次，模型更换时先用新版重算比较基准。

建议首版保存站内通知，页面打开时自动刷新未读提醒，关闭网页期间的通知可以重新打开查看。离开网页也能收到的提醒需另定渠道。目前还需确认课堂验收采用哪种方式。

### 轻量排序模型与评测

每条训练记录是一个寻物描述与一条候选招领记录组成的配对。以是否为同一件实物作为标签。正例取真实匹配，负例优先取外观类似但属于其他实物的候选。输入特征用 Chinese-CLIP 余弦相似度、日期距离、校园区域匹配及时间地点缺失标记。先训练带正则化的逻辑回归，观察系数方向以及时空信息缺失时的表现。

先按实物编号分组划分，再生成配对。同一实物的照片和描述不跨训练与评测，评测使用的描述和答案留到最后。用留出的样本检查正确物品能否进入前三、时间地点缺失时排名是否合理。提醒另外检查更优候选、较差候选、重复事件和时空线索缺失的情况。三张网图只用于功能验证。训练和评测使用带实物编号、拍摄或拾取背景以及人工编写描述的校园样本。

## 三周里程碑

| 周次 | 动手任务 | 验收 |
|---|---|---|
| 第一周 | 接好 MySQL、发布与查询网页，提取 EXIF 并缓存图片向量 | 只上传照片即可发布，重启后能搜到，缺失线索仍可正常检索 |
| 第二周 | 抽取画面文字线索，接通寻物帖和更优候选提醒，采集与标注数据 | 准备至少一组更优、较差和重复候选，演示提醒只在合适时触发 |
| 第三周 | 训练并接入轻量排序模型，完成手机试用和断网彩排 | 展示模型怎样使用时空线索，在三分钟内走通照片发布、寻物检索和提醒 |
