失物招领数据流

发布照片

  1. 浏览器 → 发布路由POST /publishphoto 文件、found_on 日期、found_area 地点原文
  2. 发布函数 → 两处保存硬盘收 JPEG。MySQL 收文件名、日期、地点、EXIF JSON 和图片向量。
  3. MySQL → 浏览器生成 item_id，发布页显示物品编号和照片线索。

搜索物品

  1. 浏览器 → 搜索路由GET /?q=黑色雨伞请求字段是 q，Python 里叫 query。
  2. 查询 + MySQL 候选 → 排序一句描述生成文字向量，与每件物品已有的图片向量算相似度。
  3. 排序 → 浏览器返回最多 3 项，每项显示 id、分数、日期和地点，并生成照片地址。

加载照片

  1. 浏览器 → 照片路由GET /found-photos/3地址里的 3 传给 item_id。
  2. 物品编号 → MySQL用 id = 3 查出 photo_name。
  3. 硬盘 → 浏览器用文件名从 uploads/ 读取 JPEG 字节，显示成图片。
MySQL · 物品编号、照片文件名、填写信息、线索和向量
本机 uploads/ · 真正的图片文件
  1. 浏览器 → publish_page() GET /publish → 返回空白 publish.html 表单。 POST /publish → request.files["photo"] 接文件。request.form 接 found_on 和 found_area。
  2. publish_page() → publish_found_item(image, found_on=…, found_area=…) 文件打开成 Pillow Image。日期由字符串转为 date，地点去掉首尾空格。空日期和空地点传 None。 缺照片、无效日期、地点超长、照片读写失败 → HTTP 400。数据库写入失败 → HTTP 500。
  3. publish_found_item() 从照片得到三份数据
    read_photo_metadata(image)
    → PhotoMetadata(captured_at, latitude, longitude) → 转成 photo_clues 字典
    encode_image(clean_image)
    → 512 维归一化 float32 → 2048 字节 image_embedding
    旋转校正并转成 RGB
    → 用随机文件名写入 uploads/<UUID>.jpg → photo_name
  4. insert_found_item(photo_name, photo_clues, embedding, found_on=…, found_area=…) → MySQL connect_db() 打开连接。INSERT 保存 photo_name、photo_clues（JSON）、image_embedding、found_on（DATE 或 NULL）、found_area（原文或 NULL）。 commit() 提交，cursor.lastrowid → 整数 item_id。
  5. publish_found_item() → publish_page() → Jinja 模板 函数返回 (item_id, metadata)。render_template("publish.html", item_id=…, metadata=…) → 编号、拍摄时间及 GPS 有无。 照片拍摄时间在 photo_clues.captured_at。学生填写的拾取日期在 found_on。

请求一 · 排序结果页面

  1. GET /?q=… → search_page()request.args.get("q", "").strip() → query。打开空首页时，results = []。
  2. list_found_items() → MySQL → 候选记录connect_db() → SELECT id, found_on, found_area, image_embedding FROM found_items → 字典列表。
  3. rank_stored_items(query, items) → 匹配分数encode_text(query) → 512 维文字向量。np.frombuffer(item["image_embedding"], dtype="<f4") → 已存的 512 维图片向量。两者做点积得到 score。返回按分数降序的 [(item, score), …]，最多三项。日期与地点随记录返回，当前用于展示。
  4. render_template("search.html", query=…, results=…) → 浏览器Jinja 遍历结果，显示 item.id、score、item.found_on、item.found_area。url_for("search.found_photo", item_id=item.id) 生成 <img src>。

请求二 · 每张照片

  1. GET /found-photos/3 → found_photo(item_id=3)浏览器读到 <img src> 后单独发出请求。
  2. get_found_photo_name(item_id) → MySQLSELECT photo_name FROM found_items WHERE id = %s → 文件名或 None。
  3. send_from_directory(UPLOAD_DIR, photo_name) → 浏览器返回对应 JPEG 文件。找不到编号或文件时返回 HTTP 404。

共用函数

  • app.py创建 Flask 应用，注册 search_bp 和 publish_bp。
  • connect_db()读取本机环境变量 CAMPUS_DB_PASSWORD，返回项目 MySQL 连接，供插入和两种查询使用。
  • load_clip()无调用参数。读取本地权重和处理器配置 → 返回 (model, processor)。同一个 Flask 进程复用该模型对象。
  • _capture_time(fields) 与 _coordinate(values, direction, …)从 EXIF 时间字段得到 ISO 时间字符串，从度分秒和方向得到带正负号的小数经纬度。缺失或无效时返回 None。

终端演示函数

  • photo_metadata.py 的 main()照片路径 → read_photo_metadata(image) → 终端输出 captured_at、latitude、longitude 的 JSON。
  • chinese_clip_search.py 的 main()--query 和 --images → 枚举照片 → 调用 rank_images() → 终端输出最多三条路径和分数。
  • rank_images(query, paths, model, processor)描述和图片文件路径 → 批量计算图文向量 → 返回降序的 [(path, score), …]。search_images(query, folder) 是枚举文件夹、复用模型并取前三的早期网页演示函数。
